# FirstLook 서비스 설계 규칙 (Memory Bank)

> 이 문서는 FirstLook의 제품 의도, 서비스 원칙, 기술 경계를 기록하는 기준 문서다.
> 기능·데이터 모델·API·UI를 변경하기 전에 확인하고, 합의된 결정이 생기면 이 문서를 함께 갱신한다.

## 1. 서비스 정의

**FirstLook**은 사용자가 사진과 상황별 질문을 올리고, 다른 사용자의 빠른 YES/NO 반응을 통해 첫인상에 대한 정량적 피드백을 받는 서비스다.

- 핵심 가치: 주관적인 첫인상을 이해하기 쉬운 데이터와 피드백으로 전환한다.
- 주요 상황: 비즈니스, 소개팅/데이트, 운동/피트니스, 면접/커리어, 데일리 스타일, SNS 프로필.
- 현재 단계: 브라우저 내 동작하는 SPA 프로토타입.
- 목표 단계: 인증된 사용자가 사진을 안전하게 업로드하고, 실제 투표와 분석 결과를 받을 수 있는 웹 서비스.

## 2. 사용자와 핵심 흐름

### 역할

- **업로더**: 사진, 카테고리, 질문을 등록하고 결과를 확인한다.
- **평가자**: 피드를 탐색하며 각 카드에 한 번씩 YES 또는 NO로 반응한다.
- **운영자**: 신고·콘텐츠 검토·안전 정책을 관리한다.

### 핵심 여정

1. 업로더가 사진과 질문, 카테고리를 등록한다.
2. 서비스는 공개 전 정책 검토 상태를 관리한다.
3. 평가자가 피드에서 카드를 보고 YES/NO로 응답한다.
4. 업로더는 득표 수, 긍정률, 카테고리별 통계를 확인한다.
5. 기준을 충족한 콘텐츠는 랭킹에 노출될 수 있다.

## 3. 제품 규칙

- 질문은 하나의 첫인상 판단에 집중하고, 평가자는 YES/NO 중 하나만 선택한다.
- 투표 결과는 충분한 표본이 쌓이기 전까지 확정적 평가처럼 표현하지 않는다.
- 랭킹은 단순 긍정률뿐 아니라 최소 투표 수와 신뢰도 기준을 함께 고려한다.
- 사용자는 본인이 올린 콘텐츠를 삭제할 수 있어야 하며, 삭제 시 원본 이미지와 연결된 공개 노출을 함께 제거한다.
- 카테고리별 색상과 문구는 일관되게 유지한다.
- 현재 프로토타입의 localStorage 데이터는 실제 서비스 데이터로 간주하지 않는다.

## 4. 안전·프라이버시 원칙

- 사진은 민감한 개인 데이터로 취급한다. 업로드·열람·삭제 권한을 명확히 분리한다.
- 실명, 연락처, 위치, 타인의 개인정보가 포함된 콘텐츠는 제한하거나 신고·검토 흐름을 둔다.
- 외모 비하, 차별, 성적 대상화, 괴롭힘을 유도하는 질문과 댓글은 허용하지 않는다.
- 미성년자로 의심되는 인물의 사진은 별도 보호 정책과 검토 없이는 공개하지 않는다.
- 원본 이미지 URL, 인증 토큰, 개인 식별 정보는 클라이언트 코드나 Git 저장소에 기록하지 않는다.
- 분석 결과는 참고용 피드백이며 사람의 가치·능력에 대한 단정으로 표현하지 않는다.

## 5. 기술 설계 원칙

- 프론트엔드, API, 인증, DB, 이미지 저장소를 분리한다.
- 클라이언트는 직접 DB 또는 비밀 키에 접근하지 않는다.
- 모든 변경 API는 인증·인가·입력 검증·감사 로그를 기본으로 한다.
- 이미지 업로드는 크기·형식 검사, 악성 파일 검사, 접근 제어가 가능한 저장소를 사용한다.
- 투표는 사용자·카드 단위 중복 방지와 비정상 트래픽 방지를 갖춘다.
- API 응답은 버전 관리하고, 오류 형식과 권한 오류를 일관되게 제공한다.
- 새로운 외부 서비스·SDK·비밀값을 추가하기 전에는 이 문서에 목적과 데이터 흐름을 기록한다.

## 6. 권장 도메인 모델

- **User**: 계정, 프로필, 역할, 상태
- **Post/Card**: 업로드 사진, 작성자, 카테고리, 질문, 공개·검토 상태
- **Vote**: 카드, 평가자, 선택값, 생성 시각
- **Aggregate**: 총 투표 수, YES 수, NO 수, 긍정률, 신뢰도
- **Report/ModerationCase**: 신고 대상, 사유, 처리 상태, 운영 기록

## 7. 현재 구현과의 차이

현재 저장소는 HTML/CSS/Vanilla JavaScript 기반의 단일 페이지 프로토타입이며, 카드·투표·업로드 결과가 브라우저 localStorage에만 저장된다.

실서비스 전환 시 우선순위는 다음과 같다.

1. 사용자 인증과 계정 모델
2. 안전한 이미지 업로드·저장·삭제
3. Post와 Vote API 및 영구 데이터베이스
4. 중복 방지·집계·랭킹 로직
5. 신고·검토·차단 정책과 운영 도구
6. 개인정보 처리와 서비스 약관

## 8. 작업 규칙

- 기능을 구현하거나 수정하기 전, 이 문서에 정의된 서비스 목적·안전 원칙·기술 경계를 확인한다.
- 새 결정은 `결정 기록`에 날짜와 이유를 짧게 추가한다.
- 기존 원칙을 바꾸는 작업은 코드 변경과 같은 커밋에서 이 문서도 갱신한다.
- 불명확하거나 서로 충돌하는 요구는 임의로 구현하지 않고, 먼저 이 문서에 반영할 정책 결정을 제안한다.
- 사용자에게 보이는 문구는 비판단적이고 존중하는 언어를 사용한다.
