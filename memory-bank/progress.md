> 기준 계획: `plan.md`
>
> 이 문서는 실제 완료 증거를 기준으로 단계별 진행 상태를 기록한다. 계획·기술·서비스 규칙이 변경되면 함께 검토하고 갱신한다.

## 상태 표기

- `NOT_STARTED`: 아직 착수하지 않음
- `IN_PROGRESS`: 작업 중
- `BLOCKED`: 선행 결정 또는 외부 조건이 필요함
- `DONE`: 완료 기준과 검증 근거가 기록됨
- `PREPARED`: 문서·목업 등 준비만 되었으며 단계 완료는 아님

## 다음 실행 가능한 작업

P1 결정 전에도 아래 작업은 안전하게 시작할 수 있다.

1. Vite + React + JavaScript 개발 환경 구성
2. 기존 화면을 Feature 기반 React 컴포넌트로 분리
3. CSS 토큰과 접근성·반응형 UI 개선
4. 샘플 데이터 기반 목업 API와 컴포넌트 테스트 작성

단, 이 작업은 실제 사용자 데이터나 외부 인증·이미지 저장소를 연결하지 않는다.

## 다음 작업 시작 안내

현재 활성 프로토타입 UI의 수동 테스트는 ‘적합’으로 완료됐다. 다음 작업은 `architecture.md`를 먼저 확인하고, React 엔트리 포인트 전환의 범위와 동등성 검증 계획을 합의한 뒤 시작한다.

다음 작업의 권장 순서는 다음과 같다.

1. `architecture.md`의 현재 실행 구조와 목표 React 구조를 검토한다.
2. React 전환의 남은 화면 동등성·테스트·품질 도구 작업 범위를 확정한다.
3. 확정된 범위에 따라 구현·검증을 진행한다.

🚨 주요 업무 알림: Feed React 전환은 빌드를 통과했지만, 사용자 수동 테스트 결과가 `적합`으로 확인되기 전에는 다음 화면 전환 작업으로 넘어가지 않는다.

## 업데이트 규칙과 알림

- `plan.md`의 단계가 시작·완료·차단·재개되면 이 문서를 같은 작업 흐름에서 갱신한다.
- 상태를 `DONE`으로 바꾸려면 완료 기준, 검증 명령 또는 검토 결과를 함께 기록한다.
- 서비스 규칙 변경 시 `TECH-AGENTS.md`, `plan.md`, 이 문서의 영향을 함께 검토한다.
- P1/P2 결정, 다음 단계 착수, 차단 요인이 발생하면 채팅에 `🚨 주요 업무 알림`으로 알린다.
- 단계가 완료되거나 문서가 갱신되면 채팅에 `✅ 진행 현황 업데이트`로 알린다.
- 단계의 다음 작업을 시작하기 전, `feature-backlog.md`의 직전 단계가 사용자 검증 `적합` 상태인지 확인한다.
- 사용자 검증용 미리보기는 이전 캐시를 재사용하지 않는다. 매번 고유 개발 서버 포트·변경 식별 쿼리를 사용하고 최신 소스 제공 여부를 확인한 뒤 링크를 공유한다.
